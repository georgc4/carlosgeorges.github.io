A Linux-capable core is an awkward thing to squeeze into a small chip allocation. My RV32 SoC could boot and run a program in simulation, but the first physical-design attempt ran out of room during detailed placement. The next question was which hardware to shrink, and what that would cost when Linux ran.

The Sv32 translation unit was a substantial part of the design. Its 16-entry TLB stores recent virtual-to-physical translations so the machine can avoid walking page tables for every access. In the baseline mapped netlist, the adapter occupied about 63,361 µm² of standard cells. That made it a useful place to start.

Half the entries, a longer boot

I parameterized the TLB and measured each version with the same Yosys/SKY130 mapping screen. Then I ran the full Linux image through the real serial-memory path and waited for BusyBox ash to execute the acceptance program.

The smaller TLB saved 11.5% of mapped cell area, while the accepted boot and program run took about 32% more cycles. Both completed the same functional gate. Those are the two numbers I need together when deciding whether the space is worth it.

Translation misses are especially interesting here because page-table walks share the same serial PSRAM path as instruction fetches and data accesses. A full-word quad read already takes 56 core cycles in serial shift states, before the rest of the transaction overhead. The machine has no instruction cache. Extra memory work has somewhere expensive to go.

Sharing hardware has a price, too

I also tried a four-entry TLB with shared address-space context, shared division logic, and a single register-file read port. The read-port change replaces two read muxes with one and adds an operand-read cycle to the core’s state machine. The focused core test grew from 795 to 867 cycles for the same 85 retired instructions.

The smallest screened variant cut mapped area by 23.7%. Its full Linux run hadn’t reached userspace within the twenty-billion-cycle limit. Several four-entry variants did reach the shell, but timed out before the acceptance program returned. I’m keeping those outcomes distinct: reaching a timeout after a working shell doesn’t establish a functional bug, and it doesn’t satisfy the complete gate either.

The layout still has to fit

Mapped cell area is an early measurement. Placement repair, clock distribution, hold fixing, and routing add their own constraints. Some of the smaller variants got as far as global routing, then failed placement during antenna repair. An official physical run inserted thousands of hold buffers before legalization failed. There’s still no routed SoC GDS from this campaign.

The experiment results keep the area, physical outcome, and Linux outcome beside each other. I’m using that record to choose the next design point: one that fits physically and still gets through a real shell interaction.
