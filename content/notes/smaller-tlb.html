My RV32 SoC boots Linux and runs a program in simulation, but the first physical-design attempt ran out of room during detailed placement. I started looking for area reductions and measuring what they did to the Linux run.

The Sv32 translation unit was a substantial part of the design. Its 16-entry TLB stores recent virtual-to-physical translations so the machine can avoid walking page tables for every access. In the baseline mapped netlist, the adapter occupied about 63,361 µm² of standard cells, so I started there.

Comparing 16 and 8 entries

I parameterized the TLB and measured each version with the same Yosys/SKY130 mapping screen. Then I ran the full Linux image through the real serial-memory path and waited for BusyBox ash to execute the acceptance program.

The smaller TLB saved 11.5% of mapped cell area, while the accepted boot and program run took about 32% more cycles. Both completed the same shell-and-program test. I need to account for both results when choosing a configuration.

A TLB miss triggers a page-table walk over the same serial PSRAM path used for instructions and data. A full-word quad read already takes 56 core cycles in serial shift states, before the rest of the transaction overhead. The machine also has no instruction cache, so extra memory accesses add up quickly.

Other area reductions

I also tried a four-entry TLB with shared address-space context, shared division logic, and a single register-file read port. The read-port change replaces two read muxes with one and adds an operand-read cycle to the core’s state machine. The focused core test grew from 795 to 867 cycles for the same 85 retired instructions.

The smallest screened variant cut mapped area by 23.7%. Its full Linux run hadn’t reached userspace within the twenty-billion-cycle limit. Several four-entry variants did reach the shell, but timed out before the acceptance program returned. Those timeouts don’t establish a functional bug. They also don’t count as a passing shell-and-program run.

Physical implementation

Mapped cell area is an early measurement. Placement repair, clock distribution, hold fixing, and routing add their own constraints. Some of the smaller variants got as far as global routing, then failed placement during antenna repair. An official physical run inserted thousands of hold buffers before legalization failed. This campaign still hasn’t produced a routed SoC GDS.

The experiment results record mapped area, physical outcome, and Linux outcome together. I’m using those measurements to choose a version that can fit and still run the shell and program.
