The first useful result from AutoSilicon was a smaller motor-control circuit. The more interesting part came afterward, when an optimization that worked for one fixed-point format stopped making sense for the others.

AutoSilicon lets a coding agent modify SystemVerilog, then checks the result with Verilator, cocotb, and Yosys targeting Sky130. Each experiment gets a commit and a record of its measurements. A change survives only if it passes the checks and improves the area/frequency tradeoff. Otherwise the harness reverts it.

What the first run found

The initial design was a field-oriented motor-control coprocessor: coordinate transforms, a CORDIC, PI controllers, and PWM generation. Claude provided substantial help with the math, microarchitecture, and RTL. My part was directing the project, specifying the work, and shaping the verification strategy.

In a recorded March run, 19 experiments produced 13 accepted changes. One revision reduced estimated cell area from 215,164 to 191,487 µm² while increasing estimated maximum frequency from 171.2 to 187.3 MHz. That is about 11% less area and 9.4% more frequency at the same historical comparison point.

These are synthesis estimates against that initial design. They are not measurements from fabricated silicon or a completed place-and-route flow. There were also other points on the frontier with slightly higher frequency and larger area.

Some changes were straightforward once the agent found them. Multiplication by 1023 became a shift and subtraction: (v << 10) - v. Registers that copied values already held stable by the controller could be removed. The interesting work was checking whether the assumptions behind each simplification actually held.

A constant is only constant within its format

One experiment replaced a Clarke-transform multiplier with shifts and adds. In the tested representation, the coefficient was 18,919, which can be written as 2¹⁴ + 2¹¹ + 2⁹ − 2⁵ + 2³ − 1. The resulting circuit was smaller.

But the RTL was parameterized. Changing the fractional width changes the integer representation of the coefficient. The hard-coded shift sequence still multiplied by 18,919. It did not automatically become the right coefficient for another format.

A later revision restored the multiply and selected appropriately scaled constants. The configuration sweep also exposed precision failures: the reported set had to exclude combinations that did not pass verification. A successful experiment had established something useful about one configuration, with a narrower scope than the parameterized module suggested.

The harness needed engineering too

The history also includes less glamorous repairs: preserving results across reverts, handling interrupted subprocesses, and fixing a scope check that accidentally included uncommitted working files. Those details determine whether a long run leaves evidence I can use.

I want to extend this to more designs and eventually physical implementation. For now, the useful outcome is a working experiment loop, some concrete RTL improvements, and a much clearer idea of what each measurement does and does not establish.
