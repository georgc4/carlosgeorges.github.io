AutoSilicon produced a smaller motor-control circuit in one synthesis run. Later, I found that one of its optimizations assumed a particular fixed-point format. The RTL was parameterized, so I had to revisit that change.

AutoSilicon lets a coding agent modify SystemVerilog, then checks the result with Verilator, cocotb, and Yosys targeting Sky130. Each experiment gets a commit and a record of its measurements. The harness keeps a change if it passes the checks and improves the area/frequency tradeoff; otherwise, it reverts it.

Initial synthesis results

The initial design was a field-oriented motor-control coprocessor: coordinate transforms, a CORDIC, PI controllers, and PWM generation. Claude provided substantial help with the math, microarchitecture, and RTL. My part was directing the project, specifying the work, and shaping the verification strategy.

In a recorded March run, 19 experiments produced 13 accepted changes. One revision reduced estimated cell area from 215,164 to 191,487 µm² and increased estimated maximum frequency from 171.2 to 187.3 MHz. That is about 11% less area and 9.4% more frequency in that comparison.

These are synthesis estimates against the initial design. They are not measurements from fabricated silicon or a completed place-and-route flow. Other revisions had slightly higher estimated frequency and larger area.

The agent replaced multiplication by 1023 with a shift and subtraction, (v << 10) - v, and removed registers that copied values already held stable by the controller. I still had to check the assumptions behind those changes in the relevant configurations.

The fixed-point format changed the coefficient

One experiment replaced a Clarke-transform multiplier with shifts and adds. In the tested representation, the coefficient was 18,919, which can be written as 2¹⁴ + 2¹¹ + 2⁹ − 2⁵ + 2³ − 1. The resulting circuit was smaller in that configuration.

The RTL was parameterized, though. Changing the fractional width changes the integer representation of the coefficient. The hard-coded shift sequence still multiplied by 18,919, which was wrong for other formats.

A later revision restored the multiply and selected appropriately scaled constants. The configuration sweep also exposed precision failures. I excluded combinations that did not pass verification from the reported results. The earlier optimization had only been checked for a narrower set of configurations.

Changes to the experiment harness

I also fixed the harness to preserve results across reverts, handle interrupted subprocesses, and keep a scope check from including uncommitted working files. Those fixes make the experiment record more reliable.

I’d like to try more designs and eventually run the flow through physical implementation. For now, AutoSilicon has a working experiment loop and several RTL changes measured in synthesis. The fixed-point case is a reminder to check every supported configuration before treating an optimization as general.
