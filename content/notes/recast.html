Recast gives you a set of lettered dice and asks you to arrange them into a crossword. The rules are easy to describe. Producing letters that leave room for several satisfying answers has taken much more work.

I built the iPhone game in SwiftUI and a Python pipeline to generate its puzzle data. The pipeline works through vocabulary, letter groups, dice faces, and candidate solutions. The game scores the resulting board using its words, geometry, and semantic relationships.

The solo game is on the App Store. Version 1.1, released in March, improved battery behavior and Daily puzzles and expanded the accepted dictionary. The curation and Daily scheduling work described below comes from subsequent development; it is ahead of the current App Store release.

Three answers can still be one idea

A solver can tell me that a roll is solvable. It can return several solutions. Neither result tells me very much about how different those solutions will feel.

Suppose three boards all depend on the same long word, with a few short words rearranged around it. There are three layouts in the database, but the player is still being pushed toward one idea. Counting solutions was giving that roll too much credit.

Rejecting repeated letters was too blunt a fix. One twelve-letter roll, EPLESLPPAADA, supports APPALL with SPADE and APE, LAPSED with APPLE and LAP, or APPEASE with PALLED. The repeated letters leave room for different plans. Another roll kept returning THATCH and HATCH as its main anchors. Changing the supporting words did little to change the puzzle.

The newer curation pass looks at competitive scores, long anchors, related spellings, shared words, and board shapes. It groups close relatives and anagrams so that several versions of an idea do not count as independent strategies. Repetition can earn an exception when the stored boards provide evidence for it.

The Daily puzzle has an identity

There was also a more concrete correctness problem. A scheduled Daily could retain one roll's letters while a lookup attached solutions from another. A deterministic random selection could repeat puzzles even while most of the corpus remained unused.

The revised path makes the scheduled letters authoritative. Before using a stored solution, it checks the roll identity, letters, cell count, and board bounds. The schedule consumes the curated queue in order, then extends it from the solved database without reusing those entries.

Updating the corpus introduced a compatibility constraint: installed apps still carry their own puzzle-space lists and Daily queues. A smaller database must continue answering those older lookups.

The August data release reduced the corpus from 77,472 to 25,181 rolls and from about 64.5 to 22.7 MB. It kept 407 compatibility rolls so those older assets could still resolve. That data release is public; the newer app behavior still requires its own release.

The curation rules remain heuristics. Three stored solver answers do not describe everything a person could discover, and an algorithmic label does not establish that a puzzle is fun. The next useful feedback is people playing the boards. I now have a better way to choose which boards to put in front of them.
