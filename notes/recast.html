RECAST / PUZZLE DESIGN

Choosing better puzzles for Recast

How I choose dice that support different ways to play and keep Daily puzzle data consistent.

Carlos GeorgesSeptember 25, 20263 min read

In Recast, you roll letter dice and arrange them into a crossword. I’ve been working on how to choose dice that give players more than one reasonable way to build a board.

I built the iPhone game in SwiftUI and a Python pipeline to generate its puzzle data. The pipeline works through vocabulary, letter groups, dice faces, and candidate solutions. The game scores the resulting board using its words, geometry, and semantic relationships.

The solo game is on the App Store. Version 1.1, released in March, improved battery behavior and Daily puzzles and expanded the accepted dictionary. The curation and scheduling changes below are newer development work and are not part of that App Store release.

Choosing rolls with different solutions

The solver can tell me whether a roll is solvable and return several boards. I also want to know whether those boards require different approaches from the player.

Sometimes three boards all depend on the same long word, with a few short words rearranged around it. The database counts three layouts, but the player is still likely to find the same long word in each. A simple solution count overrates that roll.

I first tried rejecting rolls with repeated letters, but that removed some good ones. The twelve-letter roll EPLESLPPAADA supports APPALL with SPADE and APE, LAPSED with APPLE and LAP, or APPEASE with PALLED. Those are different ways to use the same letters. Another roll kept returning THATCH and HATCH as its main anchors; changing the shorter words did little to change how it played.

The newer curation pass looks at competitive scores, long anchor words, related spellings, shared words, and board shapes. It groups close relatives and anagrams so that similar boards count together. I still allow repeated letters when the stored boards show useful variety.

Daily puzzle scheduling

I also found a scheduling bug: a Daily puzzle could keep the letters from one roll while a lookup attached solutions from another. The deterministic random selection could repeat puzzles while much of the corpus remained unused.

The revised path uses the scheduled letters as the source of truth. Before using a stored solution, it checks the roll identity, letters, cell count, and board bounds. The schedule consumes the curated queue in order, then extends it from the solved database without reusing those entries.

Installed apps still carry older puzzle-space lists and Daily queues, so a smaller database must continue answering those older lookups.

The August data release reduced the corpus from 77,472 to 25,181 rolls and from about 64.5 to 22.7 MB. It kept 407 compatibility rolls so those older assets could still resolve. That data release is public; the newer app behavior still needs its own release.

The curation rules are still heuristics. Stored solver answers can’t describe everything a player might find, and the rules can’t tell me whether a puzzle is fun. I need more feedback from people playing the boards.

Sources: Recast on the App Store · August puzzle-data release.
